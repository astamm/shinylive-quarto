Goal

Build a small but complete Shiny app from scratch: UI + server, an input wired to an output, a reactive expression, and (stretch) an uploaded file. You will reconstruct, step by step, the material/apps/penguins-app/app.R used later for Shinylive.

Recommended setup: create a folder myapp/ and inside it a file app.R that you fill in at each step. Run it with the Run App button (RStudio / Positron), or shiny::runApp("myapp").

The bundled dataset is at material/apps/penguins-app/penguins.csv; copy it beside your app.R so the app can read it with readr::read_csv("penguins.csv").

1. The skeleton (UI + server)

Every Shiny app is two pieces. Start here and run it.

```r
library(shiny)

ui <- fluidPage(
  titlePanel("My first app")
)

server <- function(input, output, session) {}

shinyApp(ui, server)
```

You should see an empty page with a title. Nothing reacts yet, because there is no input or output.

2. Add an input and a text output

Add a slider and a text output, and wire them in the server.

```r
ui <- fluidPage(
  titlePanel("My first app"),
  sliderInput("n", "Number of points", min = 10, max = 200, value = 50),
  textOutput("msg")
)

server <- function(input, output, session) {
  output$msg <- renderText({
    paste("You chose", input$n, "points")
  })
}
```

Drag the slider. The text updates. Notice: input$n reads the slider, output$msg supplies the text, and renderText() wraps the R value.

3. Turn it into a plot

Add renderPlot() and a plotOutput(). Move the histogram logic out of the box with real data:

```r
library(ggplot2)
library(dplyr)

ui <- fluidPage(
  sliderInput("bins", "Bins", 5, 40, 20),
  plotOutput("hist")
)

server <- function(input, output, session) {
  penguins <- readr::read_csv("penguins.csv", show_col_types = FALSE)

  output$hist <- renderPlot({
    penguins |>
      ggplot(aes(body_mass_g)) +
      geom_histogram(bins = input$bins, fill = "#2E7D6B", color = "white")
  })
}
```

4. Add a second decoration

Add a selectInput() for the variable to plot, and use input$variable inside aes(.data[[...]]) so the plot reacts to the choice. Update the histogram accordingly. Run it.

5. Use a reactive expression

Reading the data inside renderPlot() re-reads the file every time. Move it into a reactive() so it is read once and reused:

```r
server <- function(input, output, session) {
  penguins <- readr::read_csv("penguins.csv", show_col_types = FALSE)

  df <- reactive(penguins)

  output$hist <- renderPlot({
    req(input$variable)
    df() |>
      ggplot(aes(.data[[input$variable]])) +
      geom_histogram(bins = input$bins, fill = "#2E7D6B", color = "white")
  })
}
```

Try deleting the reactive() and reading inside renderPlot(): it still works, but is slower and less clean. reactive() centralises the “source of the data”.

6. Stretch: uploaded data

Hook up an optional uploaded file that replaces the bundled data:

```r
fileInput("data", "Upload your own CSV (optional)", accept = ".csv")
```

In the server:

```r
df <- reactive({
  if (is.null(input$data)) {
    penguins
  } else {
    readr::read_csv(input$data$datapath, show_col_types = FALSE)
  }
})
```

Your app now reads a file only once the user provides one. Neither the uploaded file nor the bundled data ever leave the app: this is the property that matters for Shinylive later.
